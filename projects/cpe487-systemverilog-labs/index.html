Goal

A low-latency AI inference accelerator for the Nexys A7's Artix-7 FPGA, written with high-level synthesis (HLS) so the datapath can be explored quickly while keeping deterministic, cycle-level timing. The RTL work below is the foundation: it's how I learned what the HLS tools generate and where latency comes from.

Platform

Digilent Nexys A7-100T (Xilinx Artix-7), Vivado, SystemVerilog. Coursework for CPE 487 in Fall 2026. The VGA project is in active development.

Multiplexing four digits with one decoder

The Nexys A7's 7-segment display shares segment lines between digits, so leddec.sv lights one digit at a time (active-low anodes) and persistence of vision does the rest. Everything in hex4count is derived from one 39-bit counter clocked at 100 MHz, by choosing which bits to tap:

The detector from the previous section is wired into the counter. Its input is counter bit 29, which reads as a long run of 0s and then a 1. Every time the detector fires, the count reverses direction:

So the display counts up for about 10 seconds, then counts back down. It combines three modules: counter, FSM and display driver.

The tilt-controlled VGA ball

adxl362_reader.sv is a hand-written SPI master for the board's ADXL362 accelerometer, built as an FSM:

  • BOOT: wait 100,000 cycles (1 ms) for the sensor to power up.
  • START_WRITE: send 0x0A 0x2D 0x02 (write, POWER_CTL, measurement mode).
  • TRANSFER: shift bits at 2 MHz (100 MHz ÷ 50), sampling MISO on rising edges and shifting MOSI on falling edges.
  • PAUSE → START_READ: send 0x0B 0x0E (read from XDATA_L) and clock in 4 bytes, then swap them, because the sensor sends the low byte first.

user_motion.sv maps the signed X/Y tilt to the player's ball velocity, bot_motion.sv drives an opponent, and the ball renders over VGA timing from a 108 MHz pixel clock (Clocking Wizard IP).
